# 模型调用成本和审核质量

压测一律打 mock-llm，mock 的调用也记账，但单价为 0。这份文档里的调用次数、token 和费用都来自真模型（DeepSeek），具体是在 540 条标注样本上跑审核评估时，`ai_call` 账本记下的数据。原始结果见 `bench/results/eval/`。

## 1. 怎么跑

```bash
cp .env.example .env                      # 填 DEEPSEEK_API_KEY 和 DEEPSEEK_PRICE_*
scripts/load-gold.sh                      # 导入 eval/moderation-gold.tsv
docker compose --profile eval up -d ai-gateway-eval
curl -XPOST 'localhost:8091/admin/eval/moderation?source=sample'
curl -XPOST 'localhost:8091/admin/eval/moderation?source=hard'
curl localhost:8091/admin/cost            # 账本汇总
```

`ai-gateway-eval` 和线上网关是同一份代码、同一套提示词、同一个解析器，解析失败时同样重试一次，差别只在模型地址和单价。它不接入压测流量。

## 2. 样本和标注

| 集合 | 条数 | 来源 | 说明 |
|---|---|---|---|
| sample | 500（PASS 467 / REVIEW 17 / REJECT 16） | 从 1000 万条生成评论里等间隔抽样 | 分布接近线上：绝大多数是正常评论 |
| hard | 40（PASS 20 / REVIEW 10 / REJECT 10） | 手写的边界用例 | 谐音和缩写辱骂（nmsl、s b）、变体联系方式（威❤信、q群）、含敏感词的正常评论（“垃圾分类”“骗子都不敢这么演”） |

有两点要说清楚：

- **标注不是独立的人工标注。** 两个集合的标签都由 Claude（写这个项目的 AI 助手）按审核提示词里的规则标注。这些规则是：辱骂、人身攻击、诅咒标 REJECT；引流、广告、联系方式标 REVIEW；其余标 PASS。所以这里测的是模型和这套规则的一致程度，不是和真人审核员的一致程度。
- **sample 集对关键词规则不公平。** 评论内容由 `datagen/Texts.java` 的模板生成，关键词规则 `KeywordRules` 也是照着同一批模板写的，所以规则在 sample 上 100% 正确，这个数字没有意义。规则和模型的真实差距看 hard 集。

## 3. 结果

模型是 `deepseek-flash`（DeepSeek-V4.1-Flash），`temperature=0`，JSON 模式，`max_tokens=200`，并关闭了思考模式。

| 集合 | 模型准确率 | 关键词规则准确率 | 解析失败（重试后） | 耗时 |
|---|---|---|---|---|
| sample（500） | 98.4% | 100%（见上文，无参考意义） | 0 | 517 s |
| hard（40） | **97.5%** | **35.0%** | 0 | 41 s |

hard 集各类的 precision / recall：

| 类别 | 模型 P / R | 规则 P / R |
|---|---|---|
| PASS（20） | 0.95 / 1.00 | 0.41 / 0.70 |
| REVIEW（10） | 1.00 / 1.00 | 0.00 / 0.00 |
| REJECT（10） | 1.00 / 0.90 | 0.00 / 0.00 |

规则在 hard 集上的问题是两头都错：

- 谐音、变体一条都拦不住：REJECT 和 REVIEW 的 recall 都是 0。
- 含关键词的正常评论被误伤：20 条 PASS 里有 6 条被判成 REJECT 或 REVIEW。

降级时用规则兜底，这就是代价。所以规则兜底只用来“送人工复核”，不直接删评论，见 `design.md` 第 5 节。

模型在 sample 集上错了 8 条：

- 6 条 REJECT 判成了 PASS：“骗子，大家别信”“诈骗团伙又来了”这类骂人的话。模型把它们当成提醒其他用户的正常评论，这一类本身就有歧义。
- 2 条 REVIEW 判成了 REJECT，属于从严。两条都是“低价代刷粉丝，vx 87654321”。

hard 集只错 1 条：“这种骗钱的课谁买谁是冤种，博主就是个骗钱的”判成了 PASS，问题和 sample 集一样，出在“骗子”这类说法上。

## 4. 调用量、token 和费用

单价来自 [DeepSeek 官网价格页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing)，单位是元 / 百万 token。

| 时段 | 输入（缓存命中） | 输入（未命中） | 输出 |
|---|---|---|---|
| 空闲时段 | 0.02 | 1 | 4 |
| 高峰时段（北京时间工作日 9–12、14–18 点） | 0.04 | 2 | 8 |

评估在 2026-11-19（周四）北京时间 09:18–09:45 进行，属于高峰时段，按高峰价记账。

账本按运行批次汇总，见 `bench/results/eval/ledger.tsv`：

| 批次 | 调用次数 | 输入 token | 缓存命中 | 输出 token | 输出打满 200 的次数 | 平均耗时 | 最长 | 费用（元） |
|---|---|---|---|---|---|---|---|---|
| 第 1 批：默认开启思考 | 560 | 110,317 | 0 | 34,514 | 17 | 1,353 ms | 3,694 ms | 0.4967 |
| 第 2 批：关闭思考（上面的结果） | 540 | 92,937 | 0 | 15,609 | 0 | 1,022 ms | 1,856 ms | 0.3107 |
| **合计** | **1,100** | **203,254** | **0** | **50,123** | | | | **0.8075** |

第 1 批的 560 次调用里包含连通性测试和解析失败后的重试。

### 4.1 踩到的坑：思考 token 计入 max_tokens

最早 `max_tokens` 是 80，连通性测试 2 条里就有 1 条解析失败，那次调用输出正好 80 token，JSON 被截断了。调到 200 以后，第 1 批里仍有 17 次调用输出打满 200 token，其中 7 条样本重试后仍然失败，全部是辱骂类评论。

直接用 curl 查看原始响应，发现 `deepseek-flash` 默认先输出 `reasoning_content`，它占用的 token（那条样本是 166 个）也计入 `max_tokens`，留给 JSON 的不够了。辱骂类评论上模型“想”得更久，所以失败集中在 REJECT 类。

请求体加上 `"thinking": {"type": "disabled"}`（配置项 `LLM_DISABLE_THINKING`）以后：

- 解析失败从 7 条降到 0；
- 输出 token 从 34,514 降到 15,609，少了 55%；
- 平均耗时从 1,353 ms 降到 1,022 ms，最长从 3,694 ms 降到 1,856 ms；
- 费用少了 37%。

准确率没有下降：sample 从 98.2% 到 98.4%，hard 都是 97.5%。

审核这种输出几十个 token 的分类任务不需要思考过程。思考模式开着，费用和延迟都会上去，还会让输出不可控。

### 4.2 缓存命中为 0

DeepSeek 的上下文缓存按前缀命中，最小粒度是 64 token。审核的系统提示词只有一百多 token，再加上每次评论不同，实测没有命中。以后如果系统提示词加长（比如放进几十条示例），缓存命中价只有未命中价的 1/50，到时候值得重新测。

## 5. 换算到线上

以第 2 批为准，每次审核平均输入 172 token、输出 29 token：

| | 高峰价 | 空闲价 |
|---|---|---|
| 每条评论审核一次 | 0.000575 元 | 0.000288 元 |
| 每天 100 万条新评论 | 575 元 / 天 | 288 元 / 天 |

网关里控制成本的手段：

- **每分钟 token 预算**：令牌桶按“输入估算 + max_tokens”预扣，调用后按实际用量补扣。预算用完立即降级到规则，不排队。账单上限 ≈ 每分钟预算 × 单价，一分钟 20 万 token 时最多约 0.4 元 / 分钟（按输入价算的上限）。
- **摘要按“视频 + 评论数档位”缓存**：一个视频一辈子最多生成 5 次摘要（<100、<1k、<1 万、<10 万、≥10 万各一次），和读流量无关。失败写 30 秒失败标记，模型故障期间不会被读流量反复触发。
- **熔断打开时不调用**：模型故障时请求直接走降级，不产生费用，也不占用网关资源。

摘要没有在真模型上评估：摘要质量缺少可量化的标注，这里只给审核的数据。压测里摘要走 mock-llm，账本有调用次数，但 token 数是 mock 按字数估的，不能用来算钱。
